# ~/.config/opencode — agent guide

## Scope

Runtime distribution and local machine config for the OpenCode plugin fleet. No product logic. No plugin implementation. No duplicate validation.

This directory is the runtime boundary between the user's machine and the fleet. Plugins load from here via OpenCode's plugin loader. This directory consumes plugin artifacts but does not produce product behavior.

## What this directory holds

- `fleet.jsonc` — EDITABLE source of truth for the plugin manifest. Edit this; regenerate `opencode.json`.
- `opencode.json` — GENERATED runtime config. Do NOT hand-edit. Contains the `plugin` array regenerated by Fleet plus user-owned sections (agent, mcp, formatter, lsp, instructions) that are preserved across regeneration.
- `.opencode-fleet.lock.json` — Drift sidecar tracking `fleet.jsonc` manifest hash and the generated plugin array. Written by `opencode-fleet generate-opencode-json`; warns on drift until `--force` is passed.
- `package.json` — fleet:* script wrappers over the `opencode-fleet` CLI. Pins Zod to `4.1.8`.
- `bun.lock` — Regenerated by `bun install`; commit alongside `package.json` changes.
- `.env` — Gitignored secrets. User-managed; never committed.
- `.env.example` — Tracked placeholders. Update when a new secret is needed; never put real values here.
- `dcp.jsonc` / `dcp-escape-hatches.md` / `dcp-prompts/` — Dynamic context pruning config.
- `command/` — User-defined OpenCode commands.
- `plugin/` — User plugin overrides ONLY. Product logic belongs in the owning plugin repo.

## Canonical contracts

ID types (`AgentRunId`, `PlanId`, `PlanSlug`, `WorkspaceId`, `CorrelationId`, `WaveId`, `TaskId`, `SpineSeq`, `ArtifactRef`, `LifecycleObjectId`, `ConcordEventId`, `FleetRunId`), the telemetry envelope, artifact ref shapes, and the canonical `HealthReport` all come from `@mazac-fox/opencode-fleet-contracts` via `@mazac-fox/opencode-host-adapter`. Do not redefine them here.

## What agents do here

- Edit `fleet.jsonc` to enable/disable plugins or update `expected_tools` counts.
- Regenerate `opencode.json` via the Fleet CLI after editing `fleet.jsonc`.
- Update `package.json` fleet script wrappers when the Fleet CLI interface changes.
- Add or update DCP prompt overrides in `dcp-prompts/overrides/` (keys must match `dcp.jsonc` `customPrompts`).
- Add or update MCP server entries in `opencode.json` under the `mcp` key.
- Update `.env.example` when a new secret placeholder is needed.
- Document behavioral conventions in this file.

## What agents do NOT do here

- Hand-edit `opencode.json` — it is generated. Edit `fleet.jsonc` instead, then regenerate.
- Add plugin implementation code. The `plugin/` directory is for user overrides only; product logic belongs in the owning plugin repo (conductor, engram, codemem, concord, host-adapter).
- Add duplicate validation logic. Fleet `doctor`, `test`, and `hygiene` already cover it.
- Commit secrets. `.env` is gitignored; use macOS Keychain or `.env` locally only.
- Create or write to `~/.config/opencode/.opencode/`. This directory is gitignored and must never hold per-project runtime artifacts; those belong in each project's worktree.
- Bump Zod without coordinating across the fleet. The pin at `4.1.8` matches the plugin SDK expectation.
- Change branch structure without reviewing the `plan-persistence-config` merge plan in `README.md`.

## Critical invariants

**`opencode.json` is GENERATED.** Never hand-edit. Edit `fleet.jsonc` and regenerate:

```bash
bun run /Users/jack.mazac/Developer/opencode-fleet/src/cli.ts generate-opencode-json --force
```

**`.opencode-fleet.lock.json` tracks drift.** If modified by hand, `fleet generate-opencode-json` warns until `--force` is passed. Commit it alongside `fleet.jsonc` and `opencode.json` as a single logical change.

**`fleet.jsonc` `expected_tools` must match actual plugin surfaces.** Update when a plugin adds or removes tools. Verify with `bun run fleet:test`. Current manifest: conductor 30 tools, engram 7 tools when enabled, host-adapter (library-only, no `plugin_ref`). Codemem, Concord, and `external_plugins` are not listed in `fleet.jsonc`.

**Zod pinned to `4.1.8`.** Do not bump without coordinating across the fleet. Set in `package.json` `dependencies` and `overrides`.

**`plugin/` is for user overrides only.** If you find product logic here, move it to the owning plugin repo (precedent: Wave 7 W7.2 moved `context_usage` to Conductor).

**`.opencode/` under this config root is gitignored.** Per-project `.opencode/` belongs in each project's worktree, not here. The global `.opencode/` was archived in Wave 7 W7.4 and must not be recreated.

**`host-adapter` is library-only.** It has no `plugin_ref` in `fleet.jsonc` and is not registered as a runtime plugin. It is a contract harness and Bun dependency only.

## Regeneration workflow

1. Edit `fleet.jsonc` (enable/disable plugin, update `expected_tools`, add/remove entries). For **registry-based** installs (no local `~/Developer` paths), start from **`examples/fleet.npm.jsonc`** in the **opencode-fleet** repo and align `plugin_ref` with `opencode_config.root`.
2. Regenerate:
   ```bash
   bun run /Users/jack.mazac/Developer/opencode-fleet/src/cli.ts generate-opencode-json --force
   ```
   Or with an explicit manifest:
   ```bash
   bun run /Users/jack.mazac/Developer/opencode-fleet/src/cli.ts generate-opencode-json --manifest /path/to/fleet.npm.jsonc --force
   ```
3. Review the diff: only the `plugin` array in `opencode.json` should change; agent/mcp/formatter/lsp/instructions sections must remain byte-identical.
4. Install updated dependencies:
   ```bash
   bun run /Users/jack.mazac/Developer/opencode-fleet/src/cli.ts install
   ```
   Or: `bun run .../opencode-fleet/src/cli.ts install --manifest /path/to/fleet.npm.jsonc`
5. Validate the full runtime contract:
   ```bash
   bun run fleet:test:full-runtime
   ```
6. Commit `fleet.jsonc` + `opencode.json` + `.opencode-fleet.lock.json` + `package.json` + `bun.lock` as a single logical commit.

### Consumer vs maintainer manifests

| Goal | Manifest pattern |
|------|------------------|
| End users / CI | **`source.kind: "package"`** + `version`, `plugin_ref` under `~/…/node_modules/…` (see **opencode-fleet** `examples/fleet.npm.jsonc`) |
| Maintainers | **`source.kind: "file"`** + `~/Developer/…` (see `examples/fleet.local.jsonc`) or npm manifest + **`package.json` overrides** to `file:` local checkouts |

Do not commit machine-specific **`/Users/...`** `file:` paths. Use tilde paths or overrides.

## Validation before commit

```bash
bun run fleet:doctor -- --json         # quick health: paths, telemetry sink shape
bun run fleet:test -- --json           # runtime contract: enabled plugins, expected_tools
bun run fleet:test:full-runtime        # full profile: all plugins including disabled
bun run fleet:hygiene -- --strict --json  # lockfile and toolchain hygiene
bun run check                          # fleet:doctor + fleet:test + local no-op test
```

Validate with `bun run fleet:doctor -- --json` and `bun run fleet:test -- --json`; exact check counts depend on which plugins are enabled in `fleet.jsonc`.

## Secrets handling

- `.env` is gitignored. Never commit.
- `.env.example` is tracked — update placeholders when a new secret is needed; never put real credentials here.
- macOS Keychain for Exa and Motif (inspect with `security find-generic-password -s <service> -w`).
- Bedrock and OpenAI via env vars or AWS config (see `.env.example` for variable names).
- Fleet reports and telemetry must never include raw secrets, API keys, prompts, or payloads.
